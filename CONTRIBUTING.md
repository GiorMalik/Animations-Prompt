# Contribution & Reference-Image Guidelines

Welcome contributions: reference images for existing styles, index fixes, or runnable code animations. Before submitting, confirm the ID to avoid duplicate image contributions; there is no need to rewrite the original style prompts.

## Reference images

- Recommended 1920×1080, 16:9, with the filename matching the corresponding prompt, e.g. `K1_Flat_Vector.jpg`. By default, previews should show the pure image; put the name, feature notes, and color palette in the accompanying description so the thumbnail still conveys the style.
- One image focuses on one style; when comparing multiple styles, use the same scene where possible. The existing K1–K3 are the first community info cards, kept as-is — not a layout others must follow.
- For code-generated images, please attach the SVG, HTML, or generation script where possible, and describe the rendering method, size, fonts, and dependencies. If only a JPG is available, label it honestly — do not claim editable source code has been provided.
- Credit the author, source, and applicable license or sharing terms; for original submissions, state clearly whether you agree to the repository's free-use, modification, and sharing terms. Third-party works keep their own licenses and attribution. Do not claim unconfirmed material as original, and do not label everything MIT.

## Sources & Index

1. `docs/source-manifest.json` is the fixed baseline for the translated file set — do not overwrite its hashes just to make validation pass. If files change on purpose, regenerate the manifest and record the change in `skills/code-animation-prompts/references/library-changes.json`.
2. Register new files or intentional modifications in `skills/code-animation-prompts/references/library-changes.json`: the current SHA-256, the reason, and the contribution record; for modified original files, also keep an `original_sha256` matching the baseline.
3. Add the author and source to the skill's `references/attribution.md` so installed copies keep the attribution. Keep the original package's notes and licenses verbatim.
4. Update the picker and `_stats.json`, then run `python scripts/build_catalog.py`. Keep the README, SKILL, and affected showcase images in sync — don't just change the generation script.

## Pre-submission checks

```bash
python scripts/validate_repo.py
python skills/code-animation-prompts/scripts/styles.py search ink --limit 3
python skills/code-animation-prompts/scripts/styles.py show K1
```

Check that new images load, zoom, and filter in the picker; attach a preview in the PR and list the validation results.

The README images are generated by `scripts/build_visuals.py`, with counts read automatically from the catalog index. Once Playwright is installed, run:

```bash
python scripts/build_visuals.py --browser-channel chrome --skip-video
```

This command uses the local Chrome, updates the PNGs, and keeps unchanged GIFs. Without a browser channel it uses Playwright's Chromium; to rebuild the GIFs, drop `--skip-video` and make sure FFmpeg is available.
